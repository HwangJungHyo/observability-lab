## 시간 해석
- 전체 주문에는 결제 호출 대기가 포함된다. 세 시간을 합산하지 않는다.
- 결제 서비스 약 80.67ms는 모의 결제 대기 0.08초 설정과 부합한다.
- CLIENT 88.6 - 결제 SERVER 80.67 = 약 7.93ms.
- 주문 SERVER 89.24 - CLIENT 88.6 = 약 0.64ms.
- 차이는 화면 반올림값 기준이다. 순수 네트워크 지연이나 CPU 실행 시간으로 단정하지 않는다.
- CLIENT는 요청 송신 전 시작하고 SERVER는 수신 측 핸들러에서 시작하므로 시작 시각이 다르다.
- DNS·TCP 연결·HTTP 송신·스케줄링 등의 어느 구간인지 추가 계측 없이는 분리할 수 없다.
- 여러 호스트의 절대 시각 비교에는 clock skew도 고려해야 한다.
- 단일 정상 요청은 서비스 전체 평균/p95나 운영 병목의 증거가 아니다.

## 1초 지연 실험의 예상 (아직 수행하지 않음)
PAYMENT_DELAY_SECONDS를 0.08에서 1.0으로 바꾸면 인위적 대기는 920ms 증가한다.
정상 조건에서 결제 SERVER는 약 1초, CLIENT와 주문 SERVER도 대략 그만큼 길어진다.
기존 부가 비용이 같다는 가정의 산술 예시는 약 1000.67 / 1008.6 / 1009.24ms이나 실측 예측값이 아니다.
계층은 유지된다. 지연은 결제 SERVER span 시작 후 발생하므로 결제 시작 위치가 1초 뒤로 밀리는 것이 아니다.
설정된 결제 호출 timeout 2초 안에 정상 완료하면 주문201·결제200이 예상된다.
정확한 시간·상태는 6-4에서 측정하고 원복한다.
