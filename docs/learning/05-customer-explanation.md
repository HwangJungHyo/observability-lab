# 5장 고객 설명 — 로그로 장애 조사와 복구를 입증하기

고객 질문: 서버가 정상인데 왜 주문이 안 되나요?

이번 실습에서 주문 서버는 healthy였지만 결제 서비스가 중지되어 주문은 502로 실패했습니다.
서버 생존 여부와 실제 사용자 기능의 정상 여부는 구분해야 합니다.

Prometheus 메트릭으로 문제가 발생한 시간대와 오류·지연 변화를 확인했습니다.
각 컨테이너의 로그는 Alloy가 수집해 Loki에 모으고 Grafana에서 검색했습니다.
따라서 조사자가 서버마다 접속해 로그를 찾아다닐 필요 없이 한 화면에서 비교할 수 있습니다.

JSON 형식으로 서비스·응답 코드·처리 시간·오류 분류를 기록하고,
같은 주문에서 발생한 주문·결제 로그에는 같은 request_id를 전달했습니다.
중단 때는 해당 요청의 payment_unavailable 오류를 찾았고,
복구 후에는 같은 요청 ID의 주문201·결제200을 확인했습니다.
그 결과 서비스를 켰다는 사실을 넘어 주문 기능이 다시 성공함을 입증했습니다.

검증한 가치는 요청 단위 조사와 복구 확인 가능성입니다.
실제 운영 MTTR 절감률이나 고가용성은 이번 로컬 실습으로 측정하지 않았습니다.
다음 단계에서는 OpenTelemetry와 Tempo로 호출 관계와 구간별 시간을 확인합니다.
